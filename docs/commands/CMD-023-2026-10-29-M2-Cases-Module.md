## شواهد قرارداد — استخراج از `web/lib/web.js` (CMD-003)

- `CASES_PER = 10`، `EXCERPT_LEN = 160`، `CATS` شش‌گانه، پارامتر `page` تا ۵۰۰.
- چرخه‌ی وضعیت: `waiting → proposing → assigned → running → done` (schema CHECK) — برچسب‌های فارسی عیناً از نقشه‌ی ST رابط وب: «در انتظار بررسی / در حال پیشنهاد / تخصیص‌یافته / در حال انجام / بسته‌شده».
- POST: عنوان ۵..۱۲۰، توضیحات ۰..۵۰۰۰ (اختیاری)، سقف ۵ پرونده در ساعت → ۴۲۹ «سقف ثبت پرونده در یک ساعت تکمیل شده است. بعداً تلاش کنید.»
- ۴۰۴ ضدافشا: «پرونده یافت نشد.» (هم برای نبودن، هم برای بی‌مجوزی).
- دسترسی جزئیات: موکل = کامل (description)؛ وکیلِ ناشناس = خلاصه‌ی ۱۶۰نویسه‌ای؛ مدیر = کامل + اطلاعات مشتری + پیشنهادها (موبایل فعلاً فقط موکل — §۷ Bottom Tabs مشتری).

## کشف معماری ثبت‌شده — Riverpod 3 و حذف FamilyNotifier

- کلاس `FamilyNotifier` در Riverpod 3 **حذف شده** (CHANGELOG 3.0: «Removed FamilyNotifier and variants, in favour of Notifier») و دسترسی عمومی به آرگومان خانواده در Notifierهای دستی وجود ندارد.
- راه‌حل رسمی برای حالت فقط-خواندنی: **`FutureProvider.family`** با تایپ `FamilyCreate = (ref, arg)`.
- کشف دوم: Riverpod 3 خطاهای provider را **خودکار retry** می‌کند؛ برای ۴xx (۴۰۴ ضدافشا/۴۰۱ در انتظار D-6) تکرار بی‌معناست → `retry: (count, error) => null` تا پیام صادقانه ماندگار بماند. هر دو در README موبایل ثبت شد.
