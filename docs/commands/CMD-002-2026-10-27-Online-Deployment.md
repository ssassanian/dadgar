## یافته مهندسی (دلیل توقف — ماده ۲۱ و ۲۲ قانون عمومی)

این پروژه **یک سرور Node.js بلندمدت** است:

| ویژگی کد (واقعیت مستند) | سازگاری با Vercel |
|---|---|
| `server.js` = سرور HTTP همیشگی (`node server.js`) | ❌ Vercel سرورلس است؛ پردازش همیشگی ندارد |
| دیتابیس = SQLite داخلی Node در `DATA_DIR=./data` (فایل روی دیسک) | ❌ دیسک Vercel ماندگار نیست؛ داده‌ها از بین می‌رود |
| محدودکننده نرخ و نشست‌ها در حافظه (in-memory) | ❌ در سرورلس با هر فراخوانی ریست می‌شود |
| `APP_SECRET` الزامی در production (≥48 نویسه) | ⚙️ نیازمند تنظیم Env Variable در میزبان نهایی |
| README خود پروژه: «فاز ۴) راهنمای گذاشتن روی هاست» = **آینده** | توسعه‌دهنده اولیه هم هنوز میزبان نهایی را تعیین نکرده است |

**نتیجه:** دیپلوی عینی این zip روی Vercel **بدون تغییر کد ممکن نیست**. دیپلوی صرفاً-استاتیک هم یا کد سرور را لو می‌دهد یا سایتی می‌شود که ورود/پنل‌هایش کار نمی‌کند (طبق ماده ۲۲، کار نادرست انجام نمی‌شود).

> راه‌حل‌های ممکن به مدیر ارائه شد و اجرای هرکدام منتظر تایید اوست:
> 1. میزبان Node بلندمدت با دیسک ماندگار (سرور اختصاصی/VPS خودتان، یا PaaS مثل Railway/Render) — **بدون هیچ تغییر در کد**
> 2. فاز مهندسی جدید: مهاجرت به Vercel + Supabase Postgres (کدنویسی — فازبندی‌شده و فقط با تایید مدیر)
> 3. پیش‌نمایش موقت برای بازبینی (خروجی واقعی نیست)
