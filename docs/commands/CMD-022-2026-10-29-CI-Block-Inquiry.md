## متن دستور (رونوشت عینی)

> «پرداخت نمی تونم داشته باشم ببین این مشکل تا چه زمانی هست»

زمینه: مکمل CMD-021 — سه شکست آنی Mobile CI در مخزن خصوصی؛ دو راه پیشنهادی قبلی «اصلاح billing» یا «عمومی‌سازی» بود و مدیر اکنون اعلام کرد پرداخت برایش ممکن نیست.

- محیط برای **بار چهارم** ریست شده بود: بدون Flutter SDK؛ پوشه‌ی مخزن محلی به عقب برگشته بود.
- `dadgar` محلی ۱۳ کامیت عقب‌تر از origin بود → `git fetch` + `git restore` (تغییرهای صرفاً mode) + `git merge --ff-only` → هم‌گام با `43b2d18`؛ **صفر زیان** — `mobile/` (M3) و دفاتر 2.18/2.20 و CMD-020/021 همگی از origin بازگشتند.
- پوشه‌ی محلی بجا‌مانده‌ی `dadgar-mobile/` (مخزن قدیمی که طبق ACT-056 حذف شده) دست‌نخورده ماند — غیرفعال و بی‌اثر.

3. **تاریخچه**: چهار اجرای سبز در همان روز (۱۲:۲۱، ۱۳:۵۳، ۱۳:۵۷، ۱۴:۱۵ UTC؛ هرکدام ~۱٫۵–۲ دقیقه) و از ۱۶:۴۳ به بعد هر اجرا فوری می‌بُرد.
4. **فایل workflow از ابتدای مونوریپو دست‌نخورده است** (تنها کامیت 50fc7cb) و روی `ubuntu-latest` است (ضریب ۱×) — ورک‌فلو به‌هیچ‌وجه علت نیست.

## پاسخ به «تا چه زمانی؟»

- اگر نوعِ سهمیه باشد → ریست ماهانه روی **روزِ ثبت حساب** است (۱۷ اوت ساخته شده) ⇒ پنجره‌ی بعدی **~۱۷ نوامبر ۲۰۲۶ (۱۹ روز بعد)**.
- اگر نوعِ راستی‌آزمایی/مسدودسازی باشد (بر پایه‌ی شواهد، محتمل‌تر) → **تاریخ پایان قطعی و خودکار ندارد**؛ GitHub آن را فقط با افزودن روش پرداخت یا بازبینی خودش باز می‌کند.
- نتیجه‌ی عملی: بدون پرداخت، دو راه مطمئن وجود دارد:

### گزینه‌های پیش مدیر (بدون پرداخت)
| گزینه | اقدام | پیامد |
|---|---|---|
| **الف (توصیه‌شده)** | عمومی‌سازی مخزن: Settings → General → Danger Zone → Change visibility → Public | Actions مخازن عمومی **نامحدود و همیشگی رایگان** است؛ باز شدن فوری CI. کد عمومی می‌شود اما **Secrets لو نمی‌رود** (سپرات از کد است؛ اسکن‌های قبلی هم پاک بود) |
| ب | مدیر بنر `github.com/settings/billing` را می‌خواند و متن دقیق را می‌گوید | اگر «spending limit/quota» بود → صبر تا ~۱۷ نوامبر؛ اگر «verify/payment» بود → بدون کارت باز نمی‌شود |
| ج | فعلاً بی‌خیال CI — گیت کیفیت همان تست‌های محلی (analyze + ۴۸/۴۸) | توسعه کاملاً ادامه دارد؛ اجراهای CI بعداً جبرانی می‌شوند |

برای گزینه‌ی الف، در صورت صریح بودن دستور مدیر، امکان اعمال از طریق API نیز توسط عامل بررسی می‌شود؛ در غیر این صورت مدیر از مرورگر در ~۱ دقیقه انجام می‌دهد.
