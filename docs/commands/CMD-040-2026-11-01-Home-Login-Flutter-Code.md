# CMD-040 — کدنویسی طراحی‌های تاییدشده: ورود (ویترین) + خانه (کار-اول)

- **تاریخ:** ۱۴۰۴/۰۸/۱۴ (2026-11-01)
- **فرمانده:** مدیر پروژه
- **متن فرمان:** «ادامه» — تایید طراحی‌های CMD-038 و CMD-039 و آغاز کدنویسی Flutter (طبق تعهد CMD-037: «اگر اوکی بود کدنویسی بشه»)
- **وضعیت:** کدنویسی کامل شد — دروازه‌ی نهایی: Mobile CI (flutter analyze --fatal-infos + flutter test)

## دامنه‌ی اجرا

- `mobile/lib/design/journey_bar.dart` — **تازه**: ویجت مشترک عنصر امضایی «مسیر پرونده» با پنج مرحله‌ی **واقعی** قرارداد سرور (waiting→proposing→assigned→running→done از CMD-003)؛ `current=null` یعنی خنثی — هیچ مرحله‌ی جعلی «انجام‌شده» رندر نمی‌شود (S-4).
- `mobile/lib/features/auth/presentation/login_screen.dart` — بازطراحی CMD-039: برند (مونوگرام «د») → شبکه‌ی ۲×۳ شش قابلیت → نمونه‌ی مسیر پرونده با برچسب «نمایشی» → فرم ورود (منطق، اعتبارسنجی، OTP، نکته‌ی D-6 عین M1).
- `mobile/lib/features/home/home_screen.dart` — بازطراحی CMD-038: درود + امروز شمسی تهران (تقویم نیتیو، بدون شبکه) → کارت قهرمان «مسیر پرونده» + دو دکمه → سه اقدام فوری (ارسال سند/رزرو نوبت/پرداخت فاکتور) → دو پنل «پرونده‌ها و گفتگو» و «نوبت و مالی» → کارت پنل مدیریت (گیت نقش M6 حفظ) → دو چیپ وضعیت صادقانه. کارت‌های پالت M1 (نمایشگر #hex) حذف شدند — خانه دیگر ویترین توکن نیست.
- **صفر مسیر یتیم:** هر ۱۱ مقصد روتر (cases, cases/new, cases/:id, appointments, appointments/mine, invoices, admin/billing, tickets, tickets/new, threads, documents, profile) از خانه یا جریان خودش در دسترس می‌ماند.
- **تصرح داده (S-4):** قهرمانِ طراحی CMD-038 «جلسه‌ی دادگاه با شمارش روز» بود؛ قرارداد فعلی سرور فیلد جلسه ندارد و D-6 هم بسته است → پیاده‌سازی صادقانه: قهرمان = چرخه‌ی واقعی پنج‌مرحله‌ای؛ ارتقا به «جلسه‌ی بعدی» نیازمند افزوده‌ی قرارداد سرور (فرمان آینده، با گارد DDL).
