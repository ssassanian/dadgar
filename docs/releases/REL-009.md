## ۲) محتوای خروجی

- **۳ صفحه از حالت نمایشی خارج شد**: `aSet` (تنظیمات سایت — واقعی)، `aCms` (تعرفه‌ها — واقعی)، `aSeo` (سند برنامه‌ریزی — فقط نوار زرد برداشته شد) — مجموع صفحات واقعی فاز ۳: **۲۴ از ۲۳** (+۱ عمومی؛ دو صفحه‌ی aSet/aCms قبلاً در شمارش «۲۳» یک صفحه حساب می‌شدند)
- **۳ مسیر API جدید**: `GET /api/settings` (فقط مدیر)، `PUT /api/settings` (فقط مدیر، سفید‌لیست ۸ کلید + سقف طول + Audit `settings_save`)، `GET /api/settings/public` (مهمان؛ اطلاعات تماس + تعرفه‌ها) — جمع مسیرهای API: **۴۶**
- **تصمیم طراحی ثبت‌شده (جدول settings)**: اسکیمای مرجع جدول تنظیمات ندارد؛ مدل `key-value سفید‌لیست‌شده` به‌عنوان «افزوده‌ی ثبت‌شده» (نه پورت مرجع) انتخاب شد — `settings(key,value,updated_at,updated_by)` — بدون تغییر در ۱۵ جدول مرجع
- **تخریب تدریجی شفاف (ایده‌ی کلیدی این خروجی)**: اعمال DDL نیازمند دسترسی ممتاز است که فقط نزد مدیر است (`dadgar_app` عمداً بدون مجوز DDL است — CMD-002/ACT-006؛ رمز نقش `postgres` نزد مدیر). پس کد با تشخیص `42P01` شفاف degrade می‌شود: خواندن `ready:false` + مقادیر پیش‌فرض مرجع در UI؛ نوشتن 503 با پیام صادقانه. **پس از اعمال DDL توسط مدیر (`web/db/settings-pending-ddl.sql`) هیچ تغییر کد یا دیپلوی لازم نیست** و ذخیره‌سازی خودکار فعال می‌شود
- **صفحه‌ی عمومی تعرفه‌ها**: override کنترل‌شده (الگوی CMD-006) — ساختار مرجع عیناً حفظ؛ فقط سه مبلغ ذخیره‌شده جایگزین می‌شود؛ بدون داده = عین مرجع (fallback)
- **فرانت‌اند**: `web/scripts/inject-cms.py` (زنجیره‌ی CMD-003..010، idempotent) — بخش‌های نیازمند تصمیم مدیر (صفحات ثابت/مقالات/دسته‌بندی‌ها/دسترسی نقش‌ها/لوگو) نمایشی ماندند با **پیام صادقانه** و چک‌باکس‌های نمایشی غیرفعال (disabled)
- بدون تغییر در فایل مرجع `dadgar/`؛ تغییر اسکیما = فقط افزودن فایل DDL در انتظار + کامنت در `web/db/schema.sql`

## ۷) ایرادهای ثبت‌شده حین تست (کشف و اصلاح)

1. **اعمال DDL با role کم‌دسترسی ممکن نیست** (permission denied برای CREATE اسکیمای public؛ CREATE دیتابیس هم false؛ عضویت نقشی خالی) → به‌جای دور زدنِ ناامن، طراحی «افزوده‌ی ثبت‌شده + degrade شفاف» انتخاب شد — یک بار برای همیشه هم‌سو با اصل کم‌دسترسی
2. **انتساب پیشوندی env در bash** (`DBPASS=$(…) DATABASE_URL="${DBPASS}…" cmd`) قبل از تنظیم گسترش می‌یابد → الگوی هارنس (انتساب جدا) تثبیت شد
3. خطای گذرای pooler در پرس‌وجوی متادیتا (database "dadgar_app" does not exist روی کوئری سوم) — گذرا بود؛ با retry تایید شد و به کد محصولی ربطی ندارد
