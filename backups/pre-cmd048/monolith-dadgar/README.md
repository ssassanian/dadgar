# سایت موسسه حقوقی دادگر — بک‌اند امن (فاز ۱ و ۲)

این پوشه هسته‌ی امن سایت است: دیتابیس، ورود با نام‌کاربری و رمز، ورود/ثبت‌نام با کد پیامکی (آماده‌ی اتصال)،
نشست‌های امن و لایه‌های امنیتی. **بدون هیچ وابستگی بیرونی** (فقط Node.js).

## پیش‌نیاز
Node.js نسخه‌ی **۲۲٫۵ یا بالاتر** (از SQLite داخلی Node استفاده می‌شود). بررسی: `node --version`

## اجرا روی کامپیوتر خودتان
```bash
npm run seed      # ساخت دیتابیس + حساب‌های آزمایشی
npm start         # اجرای سرور روی http://127.0.0.1:3000
npm test          # ۵۳ تست خودکار امنیت و ورود (بک‌اند)
```
برای دیدن کد پیامکی در حالت آزمایشی: `DEV_SHOW_OTP=1 npm start` (کد در ترمینال چاپ می‌شود).

## حساب‌های آزمایشی (فقط برای تست)
| نقش | نام کاربری | رمز عبور |
|---|---|---|
| مدیر | `admin` | `Admin#2026` |
| وکیل | `lawyer` (و `lawyer2` تا `lawyer4`) | `Lawyer#2026` |
| مشتری | `client` | `Client#2026` |

هر حساب در **اولین ورود مجبور به تغییر رمز** است. این حساب‌ها را روی سایت واقعی نسازید؛
برای مدیر واقعی: `ADMIN_USER=owner ADMIN_PASS='رمز-قوی-۱' npm run create-admin`

## امنیت (آنچه پیاده شده و تست شده)
- **رمز عبور:** هش با scrypt (حافظه‌سخت، N=32768) + نمک تصادفی + «فلفل» (HMAC با کلید سرور). رمز خام هیچ‌جا ذخیره نمی‌شود.
- **سیاست رمز:** حداقل ۱۰ نویسه، حرف و عدد، نه شامل نام‌کاربری، نه رایج.
- **نشست:** توکن تصادفی ۲۵۶ بیتی، فقط هش آن در دیتابیس؛ کوکی `HttpOnly` + `SameSite=Strict` (+ `Secure` و پیشوند `__Host-` روی HTTPS)؛ ۳۰ دقیقه بی‌فعالیتی / ۱۲ ساعت حداکثر؛ با هر ورود توکن تازه؛ با تغییر رمز بقیه‌ی نشست‌ها بسته می‌شوند.
- **CSRF:** بررسی Origin + توکن CSRF برای هر درخواست تغییر‌دهنده + SameSite.
- **قفل تلاش ناموفق:** ۵ تلاش اشتباه ← قفل (۱ تا ۶۰ دقیقه، افزایشی)، ماندگار در دیتابیس؛ پیام خطا برای کاربر موجود و ناموجود یکسان (بدون افشای وجود حساب)؛ زمان‌بندی یکسان.
- **کد پیامکی:** ۶ رقم تصادفی، ذخیره‌ی HMAC، اعتبار ۲ دقیقه، حداکثر ۵ تلاش، فاصله‌ی ۶۰ ثانیه، سقف ۵ کد در ساعت، یک‌بارمصرف. مدیر با پیامک وارد نمی‌شود.
- **رمزنگاری داده:** شماره‌ی تلفن = HMAC (برای جست‌وجو) + AES-256-GCM؛ در فازهای بعد متن پرونده‌ها، پیام‌ها و اسناد هم AES-256-GCM می‌شوند. همه‌ی کلیدها از یک `APP_SECRET` مشتق می‌شوند.
- **هدرها:** CSP سخت‌گیر با nonce (بدون `unsafe-inline` برای اسکریپت)، HSTS، `X-Frame-Options: DENY`، `nosniff`، Referrer/Permissions-Policy.
- **سایر:** پرس‌وجوی پارامتری (ضد SQL Injection)، محدودیت حجم درخواست، محدودیت نرخ، مسدودسازی مسیرهای حساس و Path Traversal، Audit Log برای رویدادهای امنیتی.

## ورود با پیامک
فعلاً درایور `console` است (کد را فقط در لاگ سرور چاپ می‌کند). پس از گرفتن پنل پیامک، `SMS_DRIVER=http` را فعال و فایل `lib/sms.js` را مطابق مستندات سرویس‌دهنده (کاوه‌نگار، ملی‌پیامک و…) تنظیم کنید. هیچ بخش دیگری تغییر نمی‌کند.

## فاز ۲: صفحه‌ی ورود و محافظت پنل‌ها (انجام شد)
- `public/index.html` همان سایت کامل است. آدرس `http://127.0.0.1:3000` را باز کنید و از آیکن/لینک **ورود** در فوتر (یا `#/login`) وارد شوید.
- صفحه‌ی ورود سه روش دارد: **رمز عبور**، **کد پیامک** و **ثبت‌نام** (نام + شماره + رمز، سپس تایید شماره با کد).
- هر پنل فقط برای نقش خودش باز می‌شود: مشتری به پنل مشتری، وکیل به پنل وکیل، مدیر به پنل مدیر. ورود نکرده‌ها به صفحه‌ی ورود می‌روند و بعد از ورود به همان صفحه‌ای که می‌خواستند برمی‌گردند.
- حساب‌های آزمایشی در اولین ورود مجبور به تغییر رمز هستند (صفحه‌ی پروفایل واقعی، متصل به سرور).
- دکمه‌ی «خروج» نشست را در سرور هم می‌بندد. نام کاربر در منوی کناری دیده می‌شود.
- **لینک پنل‌ها از فوتر و نقشه‌ی سایت برداشته شد.**
- سایت با CSP سخت‌گیر (بدون `unsafe-inline` برای اسکریپت) کار می‌کند؛ هیچ هندلر درون‌خطی در صفحه نیست.
- **داده‌ی صفحات پنل‌ها هنوز نمایشی است** (به‌جز پروفایل). این صفحات در سایت با نوار زرد «بخش نمایشی» مشخص شده‌اند و در فاز ۳ یکی‌یکی به دیتابیس وصل می‌شوند.
- تست مرورگر واقعی (۳۱ بررسی): `python3 test/e2e-browser.py` (نیازمند Python + Playwright؛ اختیاری).
